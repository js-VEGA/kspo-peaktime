# 올팍 피크타임 — 기획서 작성용 자료 (hwp 작성 담당 채팅에 넘기는 문서)

작성일 2026-11-19. 이 폴더의 그림·표·수치만 근거로 쓰면 된다. **여기에 없는 숫자를 새로 만들어 넣지 말 것.**
공고문(안내문)의 기획서 구성: 요약 1장(활용사례명·사용 공공데이터명·요약·기대효과) + 상세 10장 이내(1 개요 / 2 독창성 / 3 구체성 / 4 활용 적절성 / 5 실현가능성·기타). 심사기준: 활용 우수성, 구체성, 독창성, 실현가능성, 공익성.

## 0. 서비스 한 줄과 핵심 메시지

- **서비스명(안): 올팍 피크타임** — 올림픽공원 주차장이 언제 붐비고 언제 빠지는지, 공연 규모에 따라 저녁 주차와 퇴장이 얼마나 달라지는지를 방문객·운영자에게 보여 주는 정적 웹 서비스.
- 공고문의 공모 예시 "공연·날씨·입출차 정보를 연계한 방문객 혼잡도 예측 및 분산 안내 서비스"와 같은 방향이다. 다만 **검증 결과를 정직하게 반영해** 정확한 점 예측 대신 "유형별 분포 + 불확실성 + 공연 규모별 저녁 집중·퇴장 피크"를 보여 준다.
- 서비스 확인 방법(상세 1-3): GitHub Pages 주소 **https://js-vega.github.io/kspo-peaktime/ (예정, 미확인)**. 저장소는 12/1에 공개하며 그날 접속 확인 후 확정한다. 확정 전에는 주소를 단정해서 쓰지 말 것.

## 4. 섹션별 작성 가이드

**요약 1장** — 활용사례명(안): "올팍 피크타임: 공연 규모에 따른 올림픽공원 주차 집중·퇴장 시간대 안내". 사용 데이터: 연계 데이터(API_CPM_009), 입출차 정보 전체구역(API_CPM_008). 요약은 '언제 몰리고 언제 빠지나 + 공연 규모에 따른 저녁 집중'을 두세 문장. 기대효과는 방문객의 시간 선택, 운영자의 인력·안내 배치, 주변 교통 분산(정량 효과를 약속하지 말고 "근거 데이터 기반의 판단 자료 제공"으로 표현).

**1. 활용사례 개요** — 1-1 이름, 1-2 기능(방문객: 한산한 2시간, 가장 붐비는 시각, 출차 몰리는 시각 / 운영자: 공연 규모별 저녁 점유·퇴장 피크, 재차↔출차 전환), 1-3 확인 방법(URL, 확정 후).

**2. 독창성** — 2-1 위 표. 2-2 배경과 우수성: ① 입출차 240만 건을 직접 가공해 기관 시간표를 **독립 검증**(상관 0.983), ② 원천 중복 14.2%와 8~9월·11~12월 공백을 발견·공개, ③ 공고 예시의 '기상 연계'를 **검증한 결과 효과가 없어** 제외하고 근거를 제시, ④ 공연일 표시가 주말과 겹쳐 '공연일 vs 비공연일' 비교가 무효임을 발견하고 **관람객 규모**로 식별. 차별점은 "맞히는 척하지 않고 불확실성과 한계를 함께 보여 주는 점".

**3. 구체성** — fig3·fig4·fig5, 표 2종, 화면 캡처로 기능을 구체적으로. 검증 방식(월 단위 롤링, 80% 구간)을 간단히.

**4. 활용 적절성** — 사회적 가치: 방문객 대기·정체 감소를 위한 시간 선택 정보, 운영자의 근거 기반 인력 배치, 공공데이터 품질 개선 환류. 효과 수치는 쓰지 말고 측정 지표 제안(예: 퇴장 피크 시간대 대기 시간, 안내 조회 수)까지만.

**5. 실현가능성** — 정적 웹(서버·DB 없음)이라 2028년까지 유지 비용이 거의 없다. 데이터 갱신은 스크립트(수집→정제→JSON 생성)를 월 1회 실행하는 방식. 소스 코드는 수상 시 제공 가능. 일정은 12/1 공개 이후를 기준으로 작성. **추가 개방이 필요한 데이터 의견(아래 6)** 를 넣는다.

## 5. 반드시 지킬 표현 (과장 방지)

- "예측"이라고 쓸 때는 "과거 같은 유형 날의 분포 기반 안내"임을 밝힌다. 점 예측의 정확도(평균 오차 약 181대, 평균의 14%)를 감추지 않는다.
- 공연 효과는 **조건부 증분**이며 인과가 아니다. "공연이 원인으로 +59대" 같은 문장 금지.
- '혼잡'은 이 자료 안에서의 상대 구분(3분위)이며 공식 혼잡도·주차 가능 대수가 아니다.
- 시간당 출차는 기록에 남은 차량만 센 값이다. 아직 나가지 않은 차량은 원천에 없다.
- 계절성은 학습하지 못했다(분석 가능한 달이 1~7월, 10월뿐인 단일 연도).
- `방문객` 값은 기관 표에서 주차대수의 3배(평일)·5배(주말·휴일)인 **파생값**이라 사용하지 않았다.

## 6. 추가 개방이 필요한 공공데이터 의견 (상세 5, 근거 포함)

1. 입출차 전체구역의 **8~9월·11~12월 누락 보완**, 매월 말일 누락(월 경계), 12/7 이후 기록. (fig1)
2. **미출차(주차 중) 차량 행 포함** 또는 현재 재차 값 별도 개방. 현재는 출차시간이 없는 행이 0건이라 출차 전 차량이 사라진다.
3. 입출차 전체구역의 **원천 중복(14.2%)** 정리.
4. 공연 정보에 **시작·종료 시각, 공연장 위치, 예매·예상 관람객 수**. 현재는 시간별 관람객 수만 있다.
5. 주말이 전부 '공연일'로 표시되는 점을 포함한 **공연 정보의 포괄 범위 설명**.
6. 대관 정보에 **날짜(기간)** 포함. 현재 대관 API에는 날짜가 없어 운영자 화면에 반영하지 못했다.
7. **주차구역별 주차면수·잔여면수**와 구역 컬럼(현재는 입출구 이름만).
8. 기상 **강수량 결측(약 86%)** 보완, `방문객`이 파생값임을 명시.

3. 기획서(hwp)는 이 문서·그림·표로 별도 채팅에서 작성하고 PDF 변환, 이메일(data@ksponco.or.kr) 발송. **접수 마감 12/1(화) 18:00.**
