## 3. 아직 모르는 것 (키 발급 후 확인)

1. 두 API의 `numOfRows` 최대값과 응답 형식. 응답 필드는 TITLE/URL/LOCAL_ID/ISSUED_DATE/DESCRIPTION/COLLECTED_DATE/REG_DT(+SUB_DESCRIPTION)로 공개돼 있어 실제 값이 DESCRIPTION 안에 묶여 있을 수 있다.
2. 날짜 필터가 없어 보인다(페이지에 미기재). 있다면 부분 수집이 가능하고, 없으면 처음부터 페이지 순회해야 한다.
3. 연계 데이터(7,803건)가 날짜×시간 단위인지, 공연이 공연별인지 건수뿐인지(G1).
4. 입출차(전체구역) API가 정말 240만 행 원자료를 주는지. 개발 계정 일 1,000건 × 페이지 크기로 수집 가능한지(G2).

## 4. 방향 수정 (판단)

브리프의 큰 틀(공연이 만드는 수요를 분리·예측, 방문자+운영자 화면, 정적 웹)은 유지하고 다음을 바꾼다.

1. **기본 수요 + 공연 증분 분해를 서비스의 중심으로 둔다.** 상시 이용이 크고 공연 효과는 저녁 시간대에 얹힌다. "공연이 있으면 몇 시에 얼마나 더 몰리는가"를 시간대별로 보여주는 쪽이 사실에 맞고, 경쟁작과 구별된다.
2. **출차(귀가) 쪽도 본다.** 입차만 다루는 출품작이 많다. 공연 종료 후 출차 집중과 귀가 시각 안내는 입출차 데이터가 있어야 가능한 차별점이다(가설, 출차 데이터로 검증 필요).
3. **데이터 수집을 2단계로 나눈다.** 연계 데이터(7,803건, 1,000건씩 8회 안쪽)를 1차 기반으로 삼는다. 240만 행 원자료는 수집 가능성이 확인될 때만 구역 분석에 쓴다. 불가하면 구역 분석은 "한계"로 적고 서비스는 전체 단위로 간다.
4. **월별주차현황 보정은 보류한다.** 비율 검증 전에는 쓰지 않는다.
5. **SHAP 패키지는 쓰지 않는다.** 이 PC의 Windows 보호 기능이 일부 컴파일 모듈을 차단한다. LightGBM 내장 `pred_contrib=True`(TreeSHAP)로 같은 해석을 한다(동작 확인함).

## 6. API 호출 시험 결과 (2026-11-13 20:20~20:40)

- 키 2개 모두 게이트웨이는 통과한다. 잘못된 키는 0.1초 만에 `403 API Key is not valid`가 오지만, 발급받은 키는 통과 후 `504 Gateway Time-out`(약 10초)이다. 즉 **키는 유효하고, 문화포털 뒤쪽 원본 서버가 응답하지 않는다.**
- 연계(API_CPM_009)는 504, 전체구역(API_CPM_008)은 504 또는 60초 읽기 시간 초과. 파라미터(numOfRows=1, 빈 keyword 등)를 바꿔도 동일했고, 약 8분간 5회 재시도해도 같았다.
- 호출을 더 반복하면 일일 한도(개발 계정 1,000건)만 소모하므로 중단했다. `src/kcisa_fetch.py`는 연속 실패 시 스스로 멈춘다.
- 따라서 **G1·G2는 아직 답하지 못했다.** 응답 형식, 페이지 한도, 연계 데이터 구조 모두 미확인이다.

## 10. 2024-07 기준선·평가 틀 (탐색용, `report/baseline_2024_07.md`)

주 단위 롤링 검증(2~5주차를 직전 주들로 예측), 평가 576시간.

- 단순 평균 기준선(요일×시각)의 MAE는 40.1대/시간(평균 입차 294.7대/시간), LightGBM q50은 45.3~47.6으로 **기준선보다 나쁘다.** 학습이 1~4주뿐이라 예상된 결과이며, 브리프 G4의 "그대로 보고한다"에 해당한다.

- 80% 구간 포괄률: LightGBM 0.69~0.71, 같은 요일×시각 경험 분위수 0.27(과거 같은 요일 표본이 1~3개뿐이라 의미 없음). 구간 보정은 더 긴 데이터에서 다시 봐야 한다.
- 이 틀(주 단위 롤링, MAE, 날짜별 피크 시각 오차, 80% 포괄률, 공연 변수 ablation)은 2025 데이터가 열리면 월 단위 롤링으로 바꿔 그대로 쓴다.

## 12. 핵심 API 복구와 G1 답 (2026-11-16 14시경)

**핵심 API 두 개가 복구됐다.** 원인은 확인하지 못했다. 차량 단위 행의 등록일시(`REG_DT`)가 2026-11-14~15라서 제공 기관이 그 무렵 데이터를 적재한 것과 관련이 있어 보이지만 추정이다.

**G1 답:** 연계 API(`API_CPM_009`)에는 **날짜×시간 단위 행**("YYYYMMDD 입출차정보(추가정보)")이 있고, 한 행에 아래 항목이 들어 있다.
`주차대수, 방문객, 기온, 풍향, 강수량, 습도, 휴일, 공연명, 공연관람객수`

## 13. 연계 시간 단위 표 점검 결과 (2026-11-16, `report/linked_eda.md`)

**쓸 수 있는 것**
- `주차대수`는 **재차(주차 중인 차량 대수) 성격**이다. 야간(0~5시)에도 평균 약 350대가 남고 오후에 평일 약 1,700대, 주말 약 2,000대까지 오른다. 2024-07 입출차로 직접 계산한 점유 대수와 시각 패턴 상관이 0.90이고 크기는 약 2~3배다(그쪽은 3개 출입구만). 입차 건수가 아님을 강하게 시사하지만 원자료 복원으로 확정해야 한다.

- 휴일 라벨, 기온, 습도, 풍향이 있다.

**쓰면 안 되는 것 / 주의할 것**
1. **`방문객`은 측정값이 아니다.** 주차대수 × 3(평일), × 5(주말·공휴일)로 예외 없이 계산된 값이다(358일 전부 일 단위로 일정). 분석 변수·목표로 쓰지 않는다.
2. **`주차대수`에 구조적 이상 구간이 있다.** 정상 일 최대는 약 2,400대인데 다음 구간은 훨씬 낮다.
   - 2025-07-31~09-30(62일): 일 최대 평균 573대
   - 2025-11-07~11-28, 12-08~12-31: 일 최대 평균 105대, 58대이고 행도 하루 4~6개뿐이다
   - 매월 말일(2/28, 3/31, 4/30, 5/31, 6/30, 10/31 등)과 1/27~31도 낮다
   - 정상으로 보이는 구간은 1/1~7/30(말일 제외), 10/1~11/6, 12/1~12/7이다. 이상 구간의 원인은 모른다.
3. **누락:** 8,760시간 중 957시간 누락. 마지막 행은 2025-12-31 14시. 11·12월은 행이 각각 281, 257개뿐이다.
4. **월별주차현황과 월 단위로 맞지 않는다**(상관 0.06). 위 이상 구간 때문에 비교 자체가 어렵다. 월별주차현황은 입차 규모 보정에 쓰지 않는다.
5. 강수량은 86%가 빈 값(0.0 기록은 469행뿐). 비가 안 온 시간이 빈 값일 가능성이 높지만 미확인이다.
6. 한 행에 공연이 여럿 이어 붙은 경우가 362행이다(콤마·개행으로 구분). 공연별 관람객 수 합산 방식은 미확인이다.

**방향 영향(중요):** 기관 집계의 `주차대수`는 연중 약 60%만 믿을 수 있다. 입출차 전체구역 API(2,411,225건)의 원자료가 8월·11~12월에도 존재하므로(8월 표본 확인), **원자료에서 재차 대수를 직접 복원**해 이상 구간을 대체하는 것이 가능하다. 이는 브리프의 "재차 복원" 아이디어가 살아나는 것이며, 기존 출품작이 하기 어려운 차별점이다. 원자료 수집이 끝나야 확정할 수 있다(`src/fetch_bulk.py allzone`, 진행 중).

**주차대수 = 재차 확정:** 기관 시간표의 `주차대수`는 해당 시각 *끝*(다음 정시)의 재차 스냅숏과 가장 잘 맞는다(상관 **0.981**, 정상일 235일 5,638시각). 해당 시 평균과는 0.966, 정시 시작 스냅숏과는 0.927.
- 크기는 기관값이 복원값보다 크다: 기관 ≈ 1.13 × 복원 + 51 (R² 0.962, 절대오차 평균 108대). 심야(0~4시)에도 약 60대 차이가 있어 '출입 기록 없이 상주하는 차량' 몫으로 보인다(추정, 미확인). 낮 시간 차이(약 300대)는 비례분.
- 출차시간이 빈 행은 0건 → 아직 나가지 않은 차량은 API에 없다. 연말에 가까울수록 과소가 커질 가능성.

**데이터 공백은 원천 자체에 있다:** 입차시간 범위 2025-01-01 ~ **2025-12-07 16:08**. 월별 입차 건수: 1월 14만, 2~7월 20~28만, **8월 6.2만, 9월 6.6만**, 10월 25.4만, **11월 5.4만, 12월 6.0만**. 일 입차 1,000건 미만인 날: 11월 24일, 12월 24일(12/8 이후 전부), 그 밖에 매월 1일씩. 기관 시간표의 이상일 123일에서 복원값 일 최대 중앙값은 517대(기관 표 560대)로 거의 같다. **즉 이상 구간은 시간표만의 오류가 아니라 원천 입출차 자체가 비어 있어서, 입출차로 복원해 채우는 계획은 성립하지 않는다.**

**결론(모델링에 쓰는 범위):**
- 학습·평가 구간: 정상일이 몰린 **2025-01 ~ 07월 + 10월**(기관 표 정상일 235일). 8~9월, 11~12월은 '관측 이상 구간'으로 표시하고 제외한다.

3. 관람객 수 변수는 **관람객 ≥8천 명인 날 저녁(17~21시) 오차를 줄인다**(롤링 412→336, LOMO 382→320). 그러나 6월·10월에는 전체 오차가 늘어 전체 MAE는 개선되지 않았다. 하이브리드는 저녁 오차를 오히려 키워 채택하지 않았다.

5. **공연일 표시는 주말과 겹친다**(주말 67일 전부 공연일, 평일 공연일은 거의 금요일). 따라서 '공연일 − 비공연일'은 요일 효과이며 공연 효과로 해석할 수 없다. 공연 효과는 같은 요일 유형 안의 관람객 규모 변동으로만 본다.
6. 같은 요일 유형 안에서 일 관람객 +1천 명당 저녁(17~21시) 평균 재차 **+59대**(95% CI 42~75, 요일·월·기온 편차 통제, n=89), 저녁 18~23시 출차 **+69건**(CI 38~100). 하루 총 입차는 CI가 0을 포함해 불확실하다. → 공연은 하루 총량보다 **저녁 집중**을 키운다. 인과 주장은 하지 않는다(조건부 증분).

**제품 방향 결정:** 예측 정확도 경쟁이 아니라 '유형별 시간대 분포 + 불확실성 + 공연 규모에 따른 저녁 집중·퇴장 피크'를 투명하게 보여 주는 서비스로 간다. 웹의 수치는 **2025 관측 분포(유형 × 시각의 중앙값·10/90%)** 와 **관람객 규모별 관측 평균(표본 수 표기)** 로 보여 주고, 예측 검증 결과는 근거로 따로 제시한다.
