## 탐색 2: 공연 일정 (KOPIS, 공연예술통합전산망)

### 공식 문서에서 확인한 것 (kopis.or.kr OPEN API 소개·API 항목확인·FAQ·인증키 발급신청 페이지, 2026-11-22 열람)
- **공연목록** `http://kopis.or.kr/openApi/restful/pblprfr`
  - 필수: `service`(키), `stdate`, `eddate`, `cpage`, `rows`(최대 100)
  - 선택: `shprfnmfct`(공연시설명), `prfplccd`(공연장코드), `signgucode` 등, 그리고 `afterdate`(그 날 이후 등록·수정분만)
  - **조회 기간은 최대 31일**(결과코드 05)이다.
  - 응답: `mt20id`, `prfnm`, `prfpdfrom`(공연시작일), `prfpdto`(공연종료일), `fcltynm`(공연시설명), `genrenm`, `prfstate`
- **공연상세** `…/pblprfr/{mt20id}`
  - `mt10id`(공연시설ID), `mt13id`(공연장ID), `prfpdfrom`·`prfpdto`, `dtguidance`(공연시간 안내 문장, 예: "토요일(15:00,17:30,20:00)"), `prfruntime`, `updatedate`
  - **회차별 날짜 목록은 없다.**
- **공연시설상세** `…/prfplc/{mt10id}`
  - 공연장별 `prfplcnm`, `mt13id`, `seatscale`(좌석규모)를 준다.
  - 문서의 예시 응답이 올림픽공원이다: `FC001247`, 공연장 11개. 예시 값은 KSPO DOME 15,000석(-01), SK핸드볼경기장 5,003석(-02), 올림픽홀 2,432석(-03), 뮤즈라이브 237석(-04), 우리금융아트홀 1,184석(-05), K-아트홀 500석(-06), 88잔디마당 10,000석(-07), 수변무대 1,000석(-08), 벨로드롬 6,000석(-09) 등이다.
  - 이 값은 문서 예시이며 현재 값인지는 키 발급 후 확인해야 한다.
- **키:**
  - KOPIS 사이트의 '인증키 발급신청'(PC 전용)에서 이메일과 활용 목적(선택지에 "공모전 참여용" 있음)을 넣으면 **신청 직후 이메일로 발급**된다.
  - 1인 1키, 양도·공유 불가.
  - 유효기간은 1년이고, 3개월 이상 쓰지 않으면 승인이 취소된다.
- **호출 제한:** 1초당 10회 호출 시 서비스가 중지된다(IP 제한). 일일 한도는 페이지에 숫자가 없어 미확인이다(개발자 가이드 PDF는 받지 않았다).
- **이용조건:**
  - 출처 표시가 의무다. 예: "출처: (재)예술경영지원센터 공연예술통합전산망(www.kopis.or.kr)". 표시하지 않으면 서비스가 중단될 수 있다.
  - 특별한 사유가 없으면 상업적 이용이 가능하다(공공데이터법 제3조 4항).
  - 재배포·가공물 공개 범위에 대한 별도 조항은 FAQ에 없어 미확인이다.
  - 신청 페이지 안내: 집계 데이터는 연계 기관 티켓 판매 시스템의 발권분 기준이라 전체 관객 수와 다를 수 있다.
- **다른 후보:**
  - 공공데이터포털의 KOPIS 예매상황판(15097812, 이용허락범위 제한 없음)은 순위·공연기간 중심이라 이번 목적에는 공연목록 API가 더 맞다.
  - 기관(한국체육산업개발) 자체의 공연·대관 API에는 날짜가 없다(이미 확인).
  - 이 밖의 공개 API 후보는 이번에 찾지 못했다.

### 우리 데이터 쪽 사정 (키 없이 계산한 것)
- 연계 시간표에서 공연명이 있는 날은 136일(773행)이고, 한 행에 여러 공연이 이어진 행은 362행이다. 월별 공연일은 1~12월에 7~15일씩이다.
- **공연명에 시설명이 없다.** 그래서 시설은 KOPIS 매칭으로만 알 수 있다.
- 공연명 분리 시 주의: 쉼표로 자르면 공연명 안의 쉼표까지 잘린다(예: "1 GO! MELympic 콘서트 주간 3위"와 "2"로 분리됨). 매칭에서는 개행을 우선 구분자로 쓰고, 정규화(괄호 종류 통일, 공백·기호 제거, 영문 소문자화)와 날짜가 겹치는 후보만 비교하는 규칙이 필요하다.
- 분석일(235일) 안의 공연일은 93일이다. 136일 중 나머지는 원천 공백 달(8·9·11·12월)에 있다.

### 키 발급 후 할 계산 (go 기준은 제안대로)
1. **목록 수집:** 2025-01~12를 31일 단위로 나눠 12구간 × 공연장 코드로 공연목록을 받는다. 공연장 코드 수는 키 발급 후 확정한다. 응답은 `data/raw/kopis/`에 캐시한다.
2. **상세 수집:** 공연별 상세를 받아 `mt13id`·`dtguidance`·기간을 확보한다. 호출 수는 공연 수와 같다.
3. **날짜 매칭률:** 136일 중 KOPIS 공연 기간이 걸치는 날의 비율을 구한다. 공연명 매칭률은 위 정규화 규칙으로 계산하고, 여러 공연이 이어진 행은 공연별로 나눠 센다.
4. **시설별 분포:** 시설별 공연 수, 매칭된 날의 일 관람객 최댓값 분포(시설별 중앙값·범위·n)를 계산한다.
5. **판정:** 날짜 매칭 70% 이상이고 시설별 표본 5 이상이면 go다. 미달이면 no-go로 두고 '공연 규모 직접 선택'을 유지한다.
6. **향후 일정:** `stdate`가 오늘 이후인 조회 건수로 수집 범위를 확인한다.

## 탐색 3: 공휴일 (2026-11-22 ~ 2027-03)
- **공식 출처:** 한국천문연구원 특일 정보(data.go.kr 15012690)
  - 무료, REST(XML), 이용허락범위 제한 없음
  - `https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService`의 공휴일 정보 조회(`solYear`, `solMonth`, `ServiceKey`)
  - 응답 필드: `locdate`, `dateName`, `isHoliday`
  - 페이지 안내: 대체공휴일은 관보 공포 이후에 반영된다.
  - 활용신청 승인 방식과 일일 한도는 이번에 읽은 페이지 본문에서 확인하지 못했다(미확인).
- **현재 코드(`HOLIDAYS_2026`)와 비교:** 범위 안 2026년 날짜는 12-25 하나이고 상수에 들어 있다. **2027년 날짜는 상수에 없다.** 2027-01-01 이후에는 공휴일도 요일로 판정된다. 영향은 해시 없이 접속할 때의 기본 선택뿐이다.
- **2027년 1~3월의 공휴일·대체공휴일 날짜는 공식 출처로 아직 확인하지 않았다.** 키를 받아 조회한 뒤 상수에 넣는다(추정 날짜는 쓰지 않는다).

1. **KOPIS 인증키 발급:** https://www.kopis.or.kr → 고객센터 → OPEN API → 인증키 발급신청(PC). 목적은 "공모전 참여용"을 고르면 된다. 이메일로 받은 키는 `.env`에 `KOPIS_SERVICE_KEY=` 이름으로 넣어 주세요. 채팅·문서에는 쓰지 마세요.
2. **공공데이터포털 특일 정보 활용신청:** https://www.data.go.kr/data/15012690/openapi.do 에서 활용신청을 해 주세요(로그인 필요). 발급된 일반 인증키는 `.env`에 `DATA_GO_KR_SERVICE_KEY=` 이름으로 넣어 주세요.
3. 키를 넣었다고 알려 주시면 탐색 2의 3~6번과 탐색 3을 실행합니다. 예상 호출 수는 KOPIS가 목록 수십 건 + 상세는 공연 수만큼, 특일 정보는 5건 이하입니다.

## 다음 단계 제안
- **혼잡도:** 화면 반영 없이 기획서 6절(추가 개방 의견)에 근거를 보강한다. 등록시간 서식 오류(분·초 = 월·일, 699/699), 정시 기록 부재, 구역별 주차면수 부재를 쓴다. 근거 펼침에 "방향은 같다(상관 0.49)" 한 줄을 넣을지는 사용자가 결정할 사항이다.

- **공휴일:** 키 발급 후 2026-12~2027-03 공휴일을 조회하고 `HOLIDAYS_2027` 상수를 추가한다. 공식 응답과 다르면 보고한다.
